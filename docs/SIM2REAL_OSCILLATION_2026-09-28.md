# kid_rl sim2real 분석: 실기 12 Hz 떨림 (2026-09-28)

다른 사람이나 모델이 이어서 원인을 분석할 수 있게 정리한 문서다. 측정값은 모두 실제로 계산한 값이고, 추정은 **(추정)**, 반증된 가설은 **(반증)** 으로 표시했다.

## 0. 요약

- **현상:** 실기에서 정책을 돌리면 서 있을 때나 걸을 때나 몸 전체가 **약 12.5 Hz로 떤다**. 4틱(80 ms)마다 한 번 도는 진동이다.
  - IMU gyro_y 표준편차는 1.2~1.8 rad/s로, 학습 분포 표준편차의 3~6배다.
  - 다리 action이 매 틱 위아래로 크게 튄다(한 스텝 사이 action 변화 평균 0.24~0.44).
- **sim:** 같은 명령을 재생하면 떨지 않는다.
  - gyro_y 표준편차는 0.00~0.13 rad/s, action 변화 평균은 0.006~0.07이다.
  - 학습 때의 관측 지연·명령 지연·무작위화를 켜도 떨지 않는다.
- **확인된 것:**
  1. 관측 조립, 시간 정렬, IMU 축 방향, ONNX 추론은 실기와 sim이 동일하다(§3).
  2. 정책의 action 떨림을 만드는 입력은 **gyro**이고, **last_action 되먹임**이 이를 증폭한다(§5). joint_vel은 영향이 거의 없다.
  3. gyro 센서 자체의 잡음은 아니다. 정책이 꺼진 동안 gyro는 매끄럽다(§5.3).
  4. 실기 로봇 전체에 기록된 target을 그대로 넣으면(open-loop), 12.8 Hz에서 **실기 다리 관절이 sim보다 8~50배 크게 움직인다**(§6).
  5. 그러나 **BAM 모터 모델 단독**(진자 하중)으로는 12.5 Hz 응답이 실측 수준(목표 진폭의 약 6~9%)으로 예측된다. mjlab의 BAM 구현도 참조 구현과 일치한다(§7).
  6. 따라서 이 차이는 BAM 모터 모델이 아니라 **전신 sim 쪽**(관성, 접촉, 구조 강성, 백래시 등)에서 오는 것으로 좁혀진다. **(추정, 미확정)**
- **해석 (추정):** 실기에서 action → 다리 → 몸통 진동 → gyro → action으로 도는 폐루프의 12 Hz 이득이 1을 넘어 발진한다. sim에서는 같은 action에 몸이 거의 반응하지 않아서 이 고리가 생기지 않는다. 정책은 gyro가 5σ로 흔들리는 상황을 학습 중에 본 적이 없다.

## 1. 시스템

- **로봇:** 25개 Dynamixel 관절, 50 Hz 정책, ros2_control(read → update → write, 20 ms 주기).
  - XH540, kp 165: 다리 pitch 6개 (hip/knee/ankle pitch)
  - MX-106, kp 134: hip_roll_crank, ankle_roll_crank 4개
  - MX-64, kp 60: torso_yaw, hip_yaw 2개
  - MX-28, kp 35: 목·팔. head_pitch만 kp 120(일부러 다르게 둠)
  - 펌웨어 I, D 게인은 0이다. 학습 BAM의 `kp_fw`와 xacro kp는 같은 값이다(확인함).
- **IMU:** EBIMU. 컨트롤러가 gyro와 projected gravity를 몸통 좌표계로 넣는다.
- **학습:** mjlab + BAM 액추에이터(Rhoban Better Actuator Models; XH540, MX-28은 사용자가 직접 식별).
  - XH540은 `bam/params/xh540/m5.json`을 쓴다.
  - 정책 50 Hz, 물리 5 ms(decimation 4).
- **관측 (86개, 순서 고정):** `base_ang_vel(3), projected_gravity(3), joint_pos−default(25), joint_vel(25), last_action(25), command(3), gait_phase sin/cos(2)`
  - 정규화기는 ONNX 안에 들어 있다.
  - 학습 정규화 std: gyro 0.239/0.265/0.378 rad/s, joint_vel 평균 0.644.
- **action:**
  - `target = clamp(default + 0.5 × clip(action, ±5), 관절 한계)`
  - 실기와 sim이 같은 식이다. 필터나 slew 제한은 없다(`policy_slew_limit` 0).
- **학습 지연 설정:**
  - 관측 지연: 0~1 정책 스텝, hold 확률 0.8
  - BAM 명령 지연: 1~2 물리 스텝(5 ms 단위). update_period 4, hold 0.6, 한 스텝에 최대 +1씩만 증가.
- **실기 측정 지연 (run2):**
  - IMU 나이 중앙값 3.5 ms
  - 관절값 나이 1.9~10.4 ms
  - 읽기 중앙값 8.5 ms, 읽기 성공률 99.4%
  - 학습 범위 안이다.
- **보행 위상:** 주기 T = 0.4 / (0.5 − asin(0.1)/π) = 0.85449 s(1.17 Hz). 첫 추론이 위상 0이다.

## 3. 검증된 것 (문제 아님)

1. **관측 파이프라인:** CSV 값으로 86차원 관측을 다시 만들어 ONNX에 넣으면 기록된 action이 재현된다(max 오차 중앙값 4e-6, p99 1e-5). real과 sim 모두 같다.
2. **시간 정렬:** gait_phase의 real−sim 차이는 최대 1.2e-5에서 6.5e-5 사이다. 실기 위상과 `policy_t_s`/T의 오차는 6e-6이다.
3. **IMU 축 일관성:** d(gravity)/dt = gravity × gyro 관계를 확인했다.
   - real: 상관 0.94 / 0.88, 기울기 0.96 / 0.97
   - sim: 0.95 / 0.95
   - 회전 명령(wz −0.19) 때 gyro_z 부호도 real −0.045, sim −0.149로 같다(실기는 덜 돈다).
4. **게인:** xacro kp와 BAM `kp_fw`가 일치한다. I, D 게인은 0이다.
5. **BAM의 MJCF damping 이중 계산 여부 (반증):**
   - MJCF의 xh540 class에 `damping=3.457`(≈ kt²/R = 3.41)과 `frictionloss=0.094`(= m5 friction_base)가 있다.
   - 하지만 BAM 액추에이터가 이 값을 0으로 만들고, 매 스텝 자체 값으로 덮어쓴다.
   - 실행 중 knee의 dof_damping은 0.0514(= friction_viscous), frictionloss는 부하에 따라 0.54 N·m(knee) / 0.12 N·m(hip)이다.
   - 이중 계산은 없다.

### 4.1 right_hip_pitch action −5 유지 원인 진단 (추가 분석)

**확인된 직접 기전:** right_hip_pitch의 last_action 입력이 큰 음수 출력을 유지하는 데 강하게 관여한다. 처음 이 상태로 진입하는 원인과 오른쪽만 그러는 근본 원인은 아직 열려 있다.

- 현재 ONNX로 sim2.csv의 2~9 s 관측을 재구성해 출력 재현: action 클립 후 최대 오차 7.1e-6, 중앙값 2.1e-6.
- 같은 관측에서 오른쪽 hip의 last_action 하나만 0으로 치환: 해당 관절 raw 출력 평균 −5.84 → −0.68. 이는 물리 상태를 바꾸지 않는 1회 추론 민감도 검사다.
- 이어서 정책 명령 0, 명목 전신 sim, 5 ms 물리 간격/20 ms 정책 주기, seed 0, CPU에서 2 s 실행했다. 아래 평균은 1~2 s 구간이다. 실기에는 변경을 적용하지 않았다.

| 조건 | right_hip_pitch action 평균 | action ≤ −4.999 비율 | 관절 위치 평균(rad) | 기록된 target−pos 평균(rad) |
|---|---|---|---|---|
| 원래 경로 | −5.00 | 100% | 0.2233 | −1.2593 |
| sim 실제 목표각에 실기와 같은 관절 한계 적용 | −5.00 | 100% | 0.2233 | −1.2593 |
| 오른쪽 hip의 last_action 입력만 매 추론 0으로 치환 | −0.5024 | 0% | 0.2322 | −0.2216 |

**해석:** 이전 음수 action → 다음 큰 음수 출력 → 클립된 −5가 다음 입력으로 들어가는 고리가 한계 출력을 유지한다. 이 짧은 실험은 해당 관절의 −5 유지 현상을 다뤘으며, 실기 12 Hz 진동의 근본 원인이나 장시간 보행 성능을 검증한 것은 아니다. last_action을 지우는 것은 진단용 개입이며 배포 수정안이 아니다.

**별도로 발견한 경로 차이:** mjlab_sim_csv.py는 CSV target을 관절 한계로 자르지만, 실제 step에는 원래 action을 넘긴다. 현재 JointPositionActionCfg는 clip=None이고 BAM 입력 경로에도 목표각의 관절 한계 처리는 없다. action=−5에서 오른쪽 hip은 기본각 0.2618 + 0.5×(−5) = −2.2382 rad를 sim 목표로 받지만, CSV에는 −1.036 rad가 기록된다. 실제 목표각 제한을 추가해도 이번 2 s 결과는 동일했으므로 이 차이가 −5 유지 현상의 직접 원인이라는 가설은 지지되지 않았다. 기존 '실기와 sim의 목표각 처리가 같다'는 설명은 폐루프의 실제 전달 경로에는 성립하지 않는다. 기존 open-loop 재생은 실기의 이미 제한된 target을 action으로 역변환하므로 이 차이만으로 해당 결과가 무효가 되는 것은 아니다.

**진단 파일:** /tmp/hip_pitch_diag.py, /tmp/hip_pitch_sim_diag.py, /tmp/hip_pitch_baseline.csv, /tmp/hip_pitch_clamp_targets.csv, /tmp/hip_pitch_hip_last_zero.csv. /tmp 파일은 임시 자료다. 정책과 실행 코드 원본은 수정하지 않았다.

## 5. 어떤 관측이 action을 흔드는가

### 5.1 학습 분포 대비 실기 관측 (z = (obs − mean)/std, ONNX 정규화기 기준, run2)

| 그룹 | 서기 real | 서기 sim | 보행 real | 보행 sim |
|---|---|---|---|---|
| gyro | **3.16** | 0.04 | **4.11** | 0.60 |
| gravity | 0.72 | 0.21 | 0.77 | 0.35 |
| joint_pos | 0.64 | 0.37 | 0.68 | 0.61 |
| joint_vel | 0.96 | 0.06 | 0.93 | 0.69 |
| last_action | 0.55 | 0.73 | 0.61 | 0.54 |

(값은 |z|의 RMS.) 가장 크게 벗어나는 항목은 gyro_y로, 서기에서 4.5σ, 보행에서 5.9σ다.

### 5.2 관측을 바꿔 넣는 실험 (ONNX만 사용, run2 27 s, 실기 관측 기반)

| 넣은 관측 | action 변화 평균 \|Δa\| | 8 Hz 이상 에너지 비율 |
|---|---|---|
| 실기 그대로 | 0.290 | 0.72 |
| joint_vel 3 Hz 저역통과 | 0.285 | 0.74 |
| gyro 3 Hz 저역통과 | 0.164 | 0.49 |
| gyro = 학습 평균(상수) | 0.167 | 0.52 |
| gyro와 vel 저역통과 | 0.155 | 0.51 |
| gyro와 vel 저역통과 + last_action을 새 출력으로 되먹임 | **0.084** | **0.21** |

- 저역통과는 앞뒤로 한 번씩 거는 1차 필터라 위상 지연이 없다. 실시간으로는 불가능하므로 민감도를 보는 용도다.
- gyro가 주 입력이고, last_action 되먹임이 증폭한다. open-loop 실험이라 인과 방향(gyro가 원인인지 결과인지)은 확정하지 못한다.

### 5.3 gyro 센서 잡음인가 (아님)

- 정책이 꺼진 SAFE_HOLD 구간(로봇을 옮기는 중)의 gyro_y는 0.7 Hz로 매끄럽게 변하고 12 Hz 성분이 없다.
- 12 Hz gyro는 몸의 실제 진동이다.

### 5.4 속도 관측 차이 (떨림과는 별개의 gap)

- **실기:** Dynamixel 속도 레지스터의 표준편차가 위치 차분(Δpos/Δt)보다 2~3배 작다.
  - right_hip_pitch: 0.54 vs 1.63
  - left_knee: 0.82 vs 1.42
  - right_ankle: 0.52 vs 1.18
- **sim:** 두 값이 같다.
- **의미 (추정):** 펌웨어가 속도를 평균 내거나 필터링하는 것으로 보인다. 실기 joint_vel 관측이 실제보다 작다.
- §5.2 결과로 보면 떨림의 직접 원인은 아니다.

## 10. 후속 (2026-09-28 저녁 ~ 09-29)

### 10.1 관측 차이 두 가지를 학습에 반영
- **joint_vel:** 실기 Dynamixel 속도 레지스터는 약 60 ms 구간 평균 속도로 보인다.
  - 위치 차분 대비 전 관절 30 ms 지연, 상관 0.98이다.
  - 2 / 5 / 12.5 Hz에서 순간 속도의 0.95 / 0.82 / 약 0.30배로, 60 ms 평균의 이론값 0.98 / 0.86 / 0.30과 맞는다.
  - 실기 위치로 계산한 60 ms 평균은 레지스터와의 RMS 오차가 0.40~0.45(레지스터 표준편차 대비)로, 20~100 ms 중 가장 작다.
  - 학습 actor의 joint_vel을 `(q(now) − q(now − 60 ms)) / 60 ms`로 바꿨다(`mdp.joint_vel_window_avg`). critic은 참값이다.
- **gyro:** 실기 컨트롤러에 1차 저역통과 필터 `imu_gyro_filter_hz`를 추가했다(`include/kid_rl/lowpass.hpp`). CSV의 `gyro_*`는 필터 후 값(정책 입력), `gyro_raw_*`는 필터 전 값이다.

### 10.4 재학습 설정 (2026-09-29 시작, 2026-09-28_12-53-20 / model_66600에서 이어서)
- **actor gyro:** 6 Hz 1차 저역통과(`mdp.imu_gyro_lowpass`, `IMU_GYRO_FILTER_HZ`). 컨트롤러 `imu_gyro_filter_hz: 6.0`과 같다.
- **actor joint_vel:** 60 ms 구간 평균.
- **armature 무작위화 (구동 관절):** 0.9~1.1 → **0.1~1.1**.
- **BAM friction·kp 무작위화 (새로 추가):** friction 0.5~1.0, kp 1.0~1.3. env마다 startup에 뽑는다.
  - `mdp.randomize_bam_dynamics`와 `bam.mjlab.BamActuator.set_friction_scale`(새로 만듦)을 쓴다.
  - mjlab joint_friction 이벤트는 BAM이 매 스텝 덮어써서 구동 관절에 효과가 없다.
- **BAM 명령 지연:** 1~2 → **1~4** 물리 스텝(최대 20 ms).
- **SmoothPPO (`tasks/smooth_ppo.py`):** actor 관측의 gyro 칸(0:3)을 N(0, 0.3²)로 흔들었을 때의 평균 action 변화 제곱을 벌한다(CAPS 방식, 계수 0.01).
  - 배포 모델 기준 L_smooth는 실기 관측 1.1, sim 관측 26이다(관절당 action 변화 0.2~1.0).
  - 학습 로그의 "Mean smooth loss"로 추적한다.
- **학습 로그:** `~/sim2real/train_2026-09-29.log`

### 10.5 재학습 모델 배포 전 확인
